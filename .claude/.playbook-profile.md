# Playbook Profili — gamelabs.js

**Ne:** `@gamebyte/gamelabsjs` — TypeScript oyun framework kütüphanesi (npm paketi).
Three.js 3D world + PixiJS 2D HUD, iki katmanlı canvas mimarisi. byte-2 host'unda
üretilen oyunların runtime'ı.

**Yapı:**
- `src/core/` — app lifecycle (GamelabsApp), DI, world/hud tabanları, view factory
- `src/modules/` — opsiyonel modüller (onscreencontrols, gamecamera, physics2d/3d, particles…)
- `tests/` — vitest, **node env** (jsdom yok → DOM'a dokunan kod ince tutulur, mantık pure function'da test edilir)
- `llms.txt` + `docs/sections/*.html` — API dokümanı; davranış değişikliğinde güncellenir

**Komutlar:** `npm test` (vitest run) · `npm run lint` · `npm run typecheck` · `npm run build` (tsup)

**Dal modeli:** `main` tek gövde; `feat/*` branch → PR → merge. Versiyon + CHANGELOG
release-please ile otomatik — **PR'larda version dosyasına dokunma.**

**Öne çıkan disiplinler:**
- `/playbook:feature` — API yüzeyi ekleyen her iş (kütüphane = her public simge kalıcı yük)
- `/playbook:ship` — rebase + iki aşamalı review (Claude + Codex)
- Breaking change reference audit: `index.ts` + `core.ts` sub-entry ihracları ve
  `llms.txt` senkron tutulmalı

**Tuzaklar:**
- View tabanları (`HudViewBase`/`WorldViewBase`/`ScreenView`/`PopupView`) imza
  değişikliğine hassas — oyunlar bunları override ediyor; ekleme yap, değiştirme.
- `AppEvents` felsefesi: state `IApp`'ten okunur, event sadece tetikler — yeni app
  state'i event payload'una değil `IApp`'e ekle.
- Kod SSR-guard'lı (`typeof window/document`) — DOM'a dokunan her yeni kod da öyle olmalı.
- Yorum idiomu: "neden" anlatan yoğun docblock; satır-içi gürültü yok.
