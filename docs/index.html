Gamelabs.js

A TypeScript skeleton + reusable modules for web games — designed for AI-generated projects, consistent structure, and strict rendering/logic separation.

Built on Three.js (3D world/scene), PixiJS (2D HUD/UI), and GSAP (animations).

Design Decisions

  • Base GamelabsApp class — extend and override methods to control program flow
  • Two DI containers: diContainer (controllers/utilities) and viewDiContainer (views)
  • Strict View–ViewController separation
    • World + WorldViews — 3D scene objects (Three.js)
    • Hud + HudViews — 2D UI overlays (PixiJS)
  • Module system for sharing features between projects

File Naming Conventions

  • Interfaces: IFoo.ts
  • HUD views: FooView.pixi.ts
  • World views: FooView.three.ts
  • Controllers: FooController.ts
  • Events: FooEvents.ts
  • Models: Foo.ts or FooModel.ts
  • Config: MyGameConfig.ts
  • Asset IDs: MyGameAssetIds.ts — enum with namespaced values like "MyGame.ItemName"
  • UI IDs: MyGameUIIds.ts — enum with namespaced values like "MyGame.GameScreen"

App Lifecycle

Your app class extends GamelabsApp and overrides these methods (called in order):

  1. registerModules() — register ModuleBinding instances with addModule()
  2. configureDI() — bind instances and singletons to DI containers
  3. configureViews() — register view/controller pairs into viewFactory
  4. loadAssets() — enqueue app-specific assets in assetManager
  5. postInitialize() — create initial screens/views, hook events (called after assets are loaded)

Runtime: onStep(timestepSeconds) — per-frame logic hook.

Cleanup: preDestroy() — unsubscribe and release resources.

Dependency Injection

  • diContainer — common tools, models, events, utilities. Given to controllers.
  • viewDiContainer — common tools, scene managers. Given to views.
  • Interface tokens use the InjectionToken pattern so interfaces can serve as DI keys:
    export const IFoo = new InjectionToken<IFoo>("IFoo")

Views

  • Define a view interface: interface IMyView extends IView { ... }
  • Implement by extending WorldViewBase (3D), HudViewBase (2D), or ScreenView/PopupView
  • Views manage scene objects, rendering, sub-views, and pointer input
  • Register: viewFactory.register(MyView, MyController)
  • Create: viewFactory.createView(MyView)

View Controllers

  • Implement IViewController<IMyView>
  • Injected with diContainer
  • Listen to view events and other events, drive view behavior through the interface
  • Must reference view interfaces, never concrete view classes
  • Use UnsubscribeBag for event cleanup

Screen Views

  • Special HUD views that cover the full canvas — only one active at a time
  • Registered with a string ID: viewFactory.registerScreen(id, View, Controller)
  • Created via UIEvents: uiEvents.createScreen(id, transition)
  • Built-in transitions: instant, fade, slide (left/right/up/down)
  • Block interaction while isInTransition is true

Popup Views

  • Stackable overlay views (dialogs, confirmations) with a full-screen input blocker
  • Registered with a string ID: viewFactory.registerPopup(id, View, Controller)
  • Created via UIEvents: uiEvents.createPopup(id)
  • Removed with uiEvents.removeTopPopup() or uiEvents.removeAllPopups()
  • Fade-in on open, fade-out on close, with isInTransition guard

Events

Events decouple communication between controllers and utilities. Each event class uses the Set<cb> + Unsubscribe pattern:

class MyEvents {
  private readonly _listeners = new Set<(data: T) => void>();

  onMyEvent(cb: (data: T) => void): Unsubscribe {
    this._listeners.add(cb);
    return () => this._listeners.delete(cb);
  }

  emitMyEvent(data: T): void {
    for (const cb of this._listeners) cb(data);
  }
}

Asset Management

  • Asset IDs are enums: enum MyAssetIds { Bg = "My.Bg" }
  • Types: HudTexture, WorldTexture, GLTF, Text
  • Load via URL: new AssetRequest(type, id, url)
  • Load from content (no URL): new AssetRequest(type, id, "", content)
  • Set manually: assetManager.setAsset(id, value)
  • All loading completes before postInitialize(). Failed assets get fallbacks.
  • Retrieve: assetManager.getAsset<T>(id)

UI Navigation (UIEvents)

UIEvents is the core event bus for screen and popup navigation. Controllers inject it from diContainer and use string IDs (never concrete view classes) to trigger navigation:

// In configureViews:
viewFactory.registerScreen(MyUIIds.GameScreen, GameScreenView, GameScreenController);
viewFactory.registerPopup(MyUIIds.WinPopup, WinPopupView, WinPopupController);

// In a controller:
uiEvents.createScreen(MyUIIds.GameScreen, transition);
uiEvents.createPopup(MyUIIds.WinPopup);
uiEvents.removeTopPopup();

UI IDs follow the same namespaced enum pattern as asset IDs: enum MyUIIds { GameScreen = "My.GameScreen" }

DevUtils

Built-in development tools accessible via this.devUtils in your app class or diContainer.getInstance(IDevUtils):

  • devUtils.logger — on-screen log panel. logger.log(msg, type?), logger.show(bool)
  • devUtils.statsPanel — FPS/render stats. statsPanel.show(bool)
  • devUtils.groundGrid — 3D ground grid helper. groundGrid.show(bool)

Module System

Modules are contained, configurable feature sets. They replicate the project folder structure:

MyModule/
├── assets/
└── src/
    ├── controllers/
    ├── events/
    ├── views/
    ├── MyModuleBinding.ts
    ├── MyModuleAssetIds.ts
    ├── MyModuleUIIds.ts
    └── index.ts
  • Must have a binding class extending ModuleBinding
  • Added in registerModules() before use
  • Assets and presets can be overridden before registration via assetRequestList.overrideRequest()

UI Components

Reusable PixiJS components. Each accepts a JSON-serializable preset object so configuration can be stored as Text assets and overridden per app.

  • ButtonComponent — pressable button with placeholder/texture background and label
  • BackgroundComponent — full-screen cover-fit background with overlay
  • ImageComponent — texture fitted into a box (contain/cover/stretch)
  • VerticalLayoutComponent — flex column container
  • HorizontalLayoutComponent — flex row container with absolute positioning support

Use UIUtils.updateFields(baseJson, overridesJson) to tweak individual preset fields.

Main Screen

Ready-to-use main menu screen with logo, play button, and settings button. Exposes MainScreenEvents for click wiring. Button and background appearance configurable via presets.

Level Progress Screen

Vertical level-list screen showing previous/current/next levels with connector sprites and a back button. Exposes LevelProgressScreenEvents.

Game Camera

Camera manager with multiple controller types: Orbital3d, Topdown2d/3d, Front2d/3d, Isometric2d/3d. Supports orthographic and perspective modes with smooth follow.

Game Grid

Grid model, grid items, presets, and a view/controller pair for tile-based gameplay. Used by the match3 and tictactoe examples.

Rules & Constraints

  • Views must NOT access diContainer — views receive viewDiContainer only
  • Controllers must NOT import or manipulate rendering objects (Three.js, PixiJS). Use IView interfaces only.
  • Controllers must reference view interfaces (IMyView), not concrete classes
  • Cross-feature communication goes through event classes, not direct controller references
  • Views must not contain game logic — they render and report input
  • Event classes must use the Set<cb> + Unsubscribe pattern
  • Use UnsubscribeBag in controllers for event cleanup
  • Asset IDs and UI IDs must be enums with namespaced string values
  • Use utilities/ for services, managers, tools — not services/
  • Modules must not depend on app-specific code
  • Do not create empty lifecycle overrides
