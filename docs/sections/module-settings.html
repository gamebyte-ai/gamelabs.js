Settings

Typed settings system with boolean toggles and number sliders. Values are persisted via StorageService (localStorage), validated on write, and broadcast via events. Includes a ready-to-use popup UI.

Setup

const settings = new SettingsBinding("MyGame");
settings.addField(new SettingsBooleanField("music", "Music", true));
settings.addField(new SettingsBooleanField("sfx", "Sound Effects", true));
settings.addField(new SettingsNumberField("volume", "Volume", 80, 0, 100, 5));
settings.addField(new SettingsNumberField("difficulty", "Difficulty", 1, 1, 10, 1));
this.addModule(settings);

Open settings popup

// From any controller:
uiEvents.createPopup(SettingsUIIds.SettingsPopup);

The popup renders toggle switches for booleans and drag sliders for numbers. Values save instantly on change.

React to changes

const events = resolver.getInstance(SettingsEvents);
events.onValueChanged((name) => {
  if (name === "music") {
    const on = manager.getBooleanValue("music");
    // toggle audio
  }
  if (name === "volume") {
    const vol = manager.getNumberValue("volume");
    // adjust volume
  }
});

Field types

  • SettingsBooleanField(name, label, defaultValue) — on/off toggle
  • SettingsNumberField(name, label, defaultValue, min, max, step) — numeric slider. step controls granularity (e.g. 1 for integers, 0.1 for decimals, 5 for coarse steps)

SettingsManager API

  • addField(field) — register a field (loads persisted value or falls back to default)
  • getBooleanValue(name): boolean / getNumberValue(name): number — typed getters
  • setBooleanValue(name, value) / setNumberValue(name, value) — validates, persists, emits event
  • getFields(): Iterable<SettingsField> — iterate all registered fields
  • resetToDefaults() — reset all fields to their default values

Persistence

Values are stored in localStorage via StorageService. The SettingsBinding constructor takes a prefix string (e.g. "MyGame") so multiple games on the same domain don't collide. Values persist across page reloads and sessions.

Validation

Number values are clamped to [min, max] and rounded to the nearest step before saving. Boolean values are type-checked. Invalid persisted data (e.g. from a schema change) falls back to the field's default.
